# 2.13 寸价签：原固件 Debug 与资源报告

日期：2026-10-21。对象：LG Innotek ESL TAG 2.13B Rev0.1，PCB 日期 2016-01-20，外壳 REBE-TZ21B。

本轮保留原固件，完成了 SWD 连接、双份 Flash 备份、RAM/寄存器读取、原程序启动断点观察、NFC 实读和图像资源还原。未向 Flash 写入自制程序，未注入 RAM 执行代码，未执行擦除、解锁或修改保护位。

## 2. 已定位的屏幕引脚

下表的端口和功能来自原固件与 DFP；活动 SPI 配置和初始化调用已有运行证据。QFN 脚号为主控封装位置，不是排线针号。尚未用万用表逐点确认测试焊盘与主控的通断关系。

| 功能 | 主控端口 | QFN48 脚号 | 说明 |
|---|---|---:|---|
| CS | PA23 | 32 | 低有效 |
| D/C | PB22 | 37 | 0=命令，1=数据 |
| RESET | PB23 | 38 | 低有效 |
| BUSY | PA27 | 39 | 原程序等待其由低变高；低电平表示忙 |
| 屏幕电源使能 | PA28 | 41 | 原程序上电置高、结束后置低 |
| SCLK | PA25 | 34 | SERCOM3 PAD3，功能 C |
| MOSI / SDIO | PA24 | 33 | SERCOM3 PAD2，功能 C；读取阶段会切成 GPIO 输入 |
| 配置中的 MISO | PA22 | 31 | SERCOM3 PAD0；不能据此断言屏幕返回数据接在此脚 |

特别注意原程序的读操作：`0x1830` 会先用 GPIO 在 PA24/PA25 上发送 `0x40`，然后将 **PA24** 改成输入读回 1 字节，最后恢复 SPI。不能直接套用只读 PA22 的四线 SPI 程序。本次对应 RAM 中读回字节为 `0x18`，很像 24 ℃的温度值；未将它当作驱动 IC 型号。

屏幕标识：`WF0213T50CZ16E41e`；FPC：`WFT0213CZ16 LW`。目前没有充分证据确认具体驱动 IC 型号。

## 3. 原屏幕初始化与刷新路径

从原程序上电路径静态得到：CS、D/C、RESET 置高；延时约 20 ms；PA28 使能电源；RESET 拉低约 20 ms，再拉高约 20 ms。

在原厂命令函数上使用硬件断点，实捕获到：

| 顺序 | 命令 | 数据 | 说明 |
|---:|---|---|---|
| 1 | `06` | `17 17 17` | 启动参数 |
| 2 | `04` | 无 | 上电，随后等待 BUSY |
| 3 | GPIO 发送 `40` | 随后读 1 字节 | 通过独立函数执行，未经过命令断点；用途推测为温度读取 |
| 4 | `00` | `0F` | 当前屏幕配置 |
| 5 | `61` | `68 00 D4` | 104×212 分辨率 |
| 6 | `50` | `77` | 当前配置 |
| 7 | `10` | 图像数据 | 原程序发送第一组画面数据 |
| 8 | `13` | 图像数据 | 原程序发送第二组画面数据 |
| 9 | `12` | 无 | 刷新 |

运行时没有逐字节暂停抓取几千字节图像数据，避免显著改变刷新时序；这份记录不是外部逻辑分析仪波形。原代码中还有刷新后的 `50 F7`、`02` 及断电处理，本次命令捕获在发送 `12` 前结束，清除断点后让原固件继续完成刷新。

用户已确认释放复位后屏幕实际刷新过。

## 5. NFC 的能力与限制

主控端口：PA16=SDA（25 脚），PA17=SCL（26 脚），SERCOM1 功能 C。PA15（24 脚）在 I²C 初始化时置高，属于 NFC 相关控制脚，具体电气作用尚未测量。

原固件块读取入口 `0x44B8`；底层 I²C 读取 `0x421C`；每块 16 字节；7 位地址 `0x55`。

实际读取块 0：

```text
04 16 9A 6A 1E 44 80 00 44 00 F0 FF E1 10 6D 00
```

UID 与资料完全一致。能力容器为 `E1 10 6D 00`，其数据区长度字段为 `0x6D×8=872` 字节；手机截图显示的 868 字节与 NDEF 可用空间口径相关，不能直接当作完整物理 EEPROM 容量。

原程序 `0x4594` 会检测 NXP 厂商字节并生成 MAC 文本 NDEF。因此 NFC 确实与主控相连，存在继续开发手机交互的路径。

目前只能判断它符合 NXP 连接式 Type 2 / NTAG I²C 类器件的行为。精确料号、版本、SRAM 直通模式及会话寄存器尚未确认。没有证明原固件已经支持手机直接传图。单个完整双色帧大于当前 NDEF 空间，后续需要研究分块传输、缓冲和主控接收流程。

本轮没有由调试脚本另外发起 NFC 写入；恢复原固件启动后，原程序执行了它本来的 NDEF 初始化逻辑。

## 6. 无线、串口、可选存储

无线通过芯片内部连接使用 SERCOM4：MOSI=PB30、MISO=PC19、SCLK=PC18、CS=PB31、RESET=PB15、IRQ=PB00、SLP_TR=PA20。这些多数为封装内部连接，不能作为板外空闲 GPIO。当前 SPI BAUD=5，结合时钟推导约为 4 MHz。尚未抓取空中数据，也未确认厂商网络配对或图像下发协议。

UART 初始化代码 `0x5774` 设置 SERCOM2、PA12/PA13、115200 波特率。板上照片有 UART_TX/RX 焊盘，但本轮没有 USB-TTL 适配器，尚未验证收发。ST-Link 的 USB 连接不能据此视为主控 UART 通道。

程序还带有一套可选 SPI NOR 访问代码：SERCOM0，PA04=MOSI、PA06=MISO、PA07=SCLK、PA05=CS，PA08 为附加控制；请求速率 10 MHz。`0x97D4` 是普通读数据路径。**代码存在不等于本板已焊存储芯片**：本次未确认外置 Flash 的实际存在、JEDEC ID 或容量；还原出的启动图像在主控内部 Flash。

USB 外设虽存在，PA24/PA25 已被屏幕占用，不能直接按带原生 USB 接口的开发板使用。

## 7. 固件入口与内存布局

地址为清除 Thumb 最低位后的指令地址；函数指针保存时通常要加 1。

| 功能 | 地址 |
|---|---|
| 启动向量表 / 初始 SP / Reset | `0x00000000` / `0x20002060` / `0x00000AA0` |
| 应用向量表 / 初始 SP / Reset | `0x00000C00` / `0x20004D88` / `0x000118BC` |
| main / 主循环 | `0x0001194C` / `0x00011974` |
| 屏幕对象创建 / 初始化 | `0x00000D6C` / `0x00001A64` |
| 屏幕命令 / 数据 / 刷新 | `0x000014BC` / `0x00001508` / `0x00001820` |
| 屏幕 GPIO 读事务 | `0x00001830` |
| 屏幕 SPI 初始化 | `0x000052B8` |
| NFC 初始化 / 块读 | `0x00004594` / `0x000044B8` |
| UART 初始化 | `0x00005774` |
| GPIO 写 / 输入读 | `0x00004000` / `0x00004054` |

应用代码与只读数据约截至 `0x14443`；初始化数据的 Flash 载入区为 `0x14444..0x1453B`。原厂参数区位于 `0x3F800` 附近。大片 `FF` 区域可能是图像库、升级或预留区域，不能仅凭空白直接认定可随意占用。

## 8. 调试连接与复位问题

ST-Link 序列号：`37FF71064E57343693001043`；探针固件：`V2J37M7`。驱动安装后设备可用。连接使用 pyOCD 的 Cortex-M 通用目标，关闭自动解锁和器件包自动调试序列。

已验证 SWD 100 kHz 和 1 MHz；1 MHz 下的 Flash 样本与初始备份一致。探针报告目标电压约 3.30 V，这不是对屏幕升压或动态供电的示波器测量。

最初观察到主控处于 `State.RESET`，DSU.STATUSA=`0x02`：SAMR21 的 CRSTEXT 复位延长位置位。根据 Microchip 器件包自带调试脚本，向 `0x41002101` 写 1 字节 `0x02` 清除该 W1C 位，原固件随后正常启动并刷新屏幕。这是“接调试器后不刷新”的一个已实测原因，不能据此排除其他供电或接线问题。

芯片有 4 个硬件断点比较器。本轮仅使用硬件断点，未向指令区写入软件断点。部分早期睡眠阶段访问遇到 AP/DP wait；最终改为在刷新命令前完成采集，最终完整捕获无报错。退出采集时已清除断点并恢复原程序执行。

## 9. 备份与前后校验

两份初始 256 KiB Flash 文件逐字节相同，SHA-256：

```text
023efc81fb12f6bbfec844374120924c8c1e8597ea3e2884af3306df3d8639c8
```

采集后再读完整 Flash，程序与初始化数据完全一致；全片只有 `0x0003F890` 一个字节由 `0x1E` 变成 `0x22`。它在原厂参数区，随原程序运行更新；其精确语义尚未定位，暂不直接称为启动计数。初始和采集后版本均已保存。

用户行、AUX1、AUX3 各 256 字节的前后内容完全一致；另有校准字节备份。读取单独 lockbits 地址曾失败，本轮没有重试解锁或改写；已通过 NVMCTRL.LOCK=`0xFFFF` 保留锁状态观察结果。

`backup_manifest.json` 列出交付文件的长度和 SHA-256；`original_boot_trace.json` 保存本轮成功的启动捕获；`hardware_snapshot.json` 是最初复位状态，`hardware_snapshot_running.json` 是释放后快照，二者不能混用。

## 10. 仍待探测的项目

1. NFC 的精确型号、版本与会话/直通配置，进一步确定手机分块传图方案。
2. UART 实际电平、焊盘通断、收发协议与可用命令，需要 USB-TTL 或相应测量设备。
3. 可选 SPI NOR 是否实际焊接、容量与原厂使用情况。
4. 无线空中协议、配对过程与图像下发，需相应射频接收/协调器资源。
5. 屏幕驱动 IC 精确型号、升压波形及刷新电流，需要更明确的器件资料或仪器。

后续编写最小固件已经有较充分的屏幕与存储备份依据；NFC 传图仍应作为独立的协议工作继续验证，不能仅凭读到 UID 就视为已经打通。

## 11. 本地资料依据

已检查用户提供的 21 张图片、`readme.txt`，以及 `Microchip.SAMR21_DFP.2.1.155.atpack` 中相关器件描述、引脚定义与调试脚本。

现有 Keil 目录为 `D:\12-keil5`，ARMCC 5.06 update 5 build 528 可运行。该 SAMR21 器件包未见可直接用于此目标的 FLM；本轮不依赖 Keil 烧录算法，未尝试用 STM32 的算法操作 SAMR21。

完整机器可读结果见 `recovered_board_resources.json`。以上“实读”“静态定位”“配置推导”“尚未确认”分别列明，避免把程序中存在的驱动误当成已验证的板载硬件。

`original_firmware_linear_disassembly.asm` 覆盖 `0x00000000..0x00013E3F`，属于静态线性反汇编。它会把向量、常量池和部分数据误译成指令，不是可直接编译的源代码，也不能据此确认每一行都会执行；本报告列出的关键入口已结合调用关系或运行断点核对。
